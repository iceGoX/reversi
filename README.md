# 黑白棋

原生网页的网络双人黑白棋。首页提供创建／加入房间，采用奶油底色与水果瓷质纹章；对局页为左侧大棋盘、右侧信息和操作栏，手机端棋盘优先。也保留同屏双人与人机练习。

## 开发

需要 Node.js 22 或更新版本，无第三方运行依赖。

```sh
npm run dev -- --port 4188
npm test
npm run check
npm run build
```

`server/app.js` 同时提供静态文件与房间 API，默认仅监听本机。`dist/` 是白名单发布产物，`release.json` 固定各文件 SHA-256；不包含设计资料、原始图、测试、私有配置或房间数据。

## 在线流程

1. 输入昵称创建房间，分享六位房间号或候场页邀请链接。
2. 第二位玩家加入，房主点击开始对局。
3. 默认房主执芭乐先手，朋友执青提后手；候场可协商交换。合法性、回合、翻转与胜负均由服务端裁判。
4. 对局中可确认认输；双方看到相同的结束结果。每局结束后也可协商交换下一局先后手；交换不会改写本局结果，再来一局需双方同意。
5. 退出进行中的房间视为本局退出，对方获胜；刷新后可从首页“回到我的房间”。

玩家身份保存在当前标签页会话中，邀请链接不包含身份令牌。房间存档仅保存令牌哈希，存储目录由 `DATA_DIR` 配置。默认使用短轮询同步，失败时禁用在线落子并自动重连。重复动作带相同请求编号不会重复执行，过期版本需同步后重试。

等待房间 2 小时、对局 24 小时、结束 1 小时没有有效状态变化会过期；最多 120 房间，同来源最多 10 房间。限制请求体大小和调用频率，未进行大规模并发测试。

## 设计与验收

- 产品名称为“黑白棋”；“芭乐”“青提”仅表示棋子阵营，不作为主标题。
- Pixso 独立文件中的 `V2` 画板为当前设计：创建、加入、候场、桌面对局、手机首页和手机对局。对局操作为“认输”和“离开对局”，邀请仅出现在候场。
- 规则见 [rule.md](rule.md)，当前检查见 [design-qa.md](design-qa.md)。本轮按用户要求重点验收 UI，网络逻辑做创建／加入、落子、同步、认输和再来一局冒烟。
- `assets/source/` 仅在本地保留原素材，实际发布只使用两枚压缩水果棋子。圆形裁切去除原始图底色，不能把原图当作带 alpha 的透明图片。

## 发布

部署子路径为 `/heibaiqi/`，服务为 `reversi`，监听服务器本机端口 8794。真实服务器、站点配置和私有发布脚本仅保留在 `.local/`；每次发布先核对实际目标，备份配置、逐文件校验，失败回滚。不要复制或覆盖其他游戏的配置、服务和存档。

源码使用 Git 管理；部署配置、房间存档、构建产物、原始素材和设计过程文件不纳入版本控制。提交、推送和部署需获得明确授权。

## 网页图标

`assets/icons/` 保存从 Pixso 导出的独立图标：浏览器小图标和 180px 主屏幕图标。替换图标时同步更新页面引用与静态资源／发布清单；文件名中的版本用于避免旧图标缓存。
